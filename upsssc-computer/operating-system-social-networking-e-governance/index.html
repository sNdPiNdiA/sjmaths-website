1. OS Architecture & Types 1. OS वास्तुकला एवं प्रकार

Kernel • Monolithic • RTOS
OS Types & Architectures ऑपरेटिंग सिस्टम प्रकार एवं संरचना
Batch OS (No Interaction) Time-Sharing (Time Quantum) Multiprogramming (CPU Busy) Real-Time OS (RTOS) (Deadlines) Monolithic Kernel (Linux) Microkernel (Minix / QNX) Unix (1969, Ritchie & Thompson)
Core Principles & Differences मूलभूत सिद्धांत एवं मुख्य अंतर
  • Operating System Role: System software acting as intermediary between computer hardware and user applications. Allocates CPU time, main memory, storage, and I/O devices. OS की भूमिका: हार्डवेयर और उपयोगकर्ता/एप्लिकेशन के मध्य मध्यस्थ प्रणाली सॉफ्टवेयर। CPU समय, मुख्य मेमोरी, स्टोरेज और I/O का प्रबंधन करता है।
  • Real-Time Operating System (RTOS): Strict time-bound processing. Hard RTOS: Missing deadline causes catastrophic system failure (e.g. missile guidance, nuclear plant, airbag, pacemaker). Soft RTOS: Missed deadline degrades quality of service without total crash (e.g. live video streaming, online gaming). रीयल-टाइम OS (RTOS): कठोर समय-सीमा। हार्ड RTOS: समय सीमा चूकने पर विनाशकारी विफलता (मिसाइल नियंत्रण, पेसमेकर, एयरबैग)। सॉफ्ट RTOS: समय चूकने पर गुणवत्ता में कमी किंतु विनाश नहीं (वीडियो स्ट्रीमिंग, ऑनलाइन गेमिंग)।
  • Kernel Architecture: Kernel is core of OS. Monolithic Kernel: All OS services (VFS, IPC, drivers, memory) run in single kernel space address (faster, but driver bug can crash system - Linux). Microkernel: Only bare essentials (IPC, scheduling, basic memory) run in kernel space; drivers and file systems run as user-space servers (highly stable - Minix, QNX). कर्नल वास्तुकला: कर्नल OS का हृदय है। मोनोलिथिक कर्नल: सभी सेवाएं कर्नल स्पेस में चलती हैं (अति तीव्र, किंतु ड्राइवर में बग से पूरा सिस्टम क्रैश - Linux)। माइक्रोकर्नल: केवल अनिवार्य सेवाएं कर्नल में, शेष यूजर स्पेस में (अत्यंत सुरक्षित - Minix, QNX)।
UPSSSC Top Note: Hard RTOS is used in missile systems and airbags; Linux uses a Monolithic kernel; Unix was developed at Bell Labs in 1969! UPSSSC मुख्य बिंदु: मिसाइल प्रणाली व एयरबैग में 'हार्ड RTOS' का उपयोग होता है; Linux में मोनोलिथिक कर्नल होता है; Unix का विकास 1969 में बेल लैब्स में हुआ था!

2. Process, Memory & Deadlocks 2. प्रोसेस शेड्यूलिंग, डेडलॉक एवं मेमोरी

FCFS • Round Robin • Banker's
Algorithms & Management एल्गोरिदम एवं संसाधन प्रबंधन
PCB (Process Control Block) FCFS (Convoy Effect) SJF (Shortest Job First) Round Robin (Time Quantum) Coffman Conditions (4 Criteria) Banker's Algorithm (Avoidance) Paging & Virtual Memory Thrashing (Page Faults)
Key Mechanics & Deadlock Conditions प्रमुख यांत्रिकी एवं डेडलॉक की शर्तें
  • Process States & Scheduling: Process transitions through: New -> Ready -> Running -> Waiting/Blocked -> Terminated. Scheduling: FCFS: Non-preemptive, suffers convoy effect. SJF: Minimizes average waiting time; risks starvation. Round Robin: Preemptive time-slicing using fixed time quantum; optimal for time-sharing. प्रोसेस अवस्थाएं व शेड्यूलिंग: प्रोसेस अवस्थाएं: न्यू -> रेडी -> रनिंग -> वेटिंग -> टर्मिनेटेड। FCFS: पहले आओ पहले पाओ (कॉनवॉय प्रभाव)। SJF: सबसे छोटे कार्य को पहले (औसत प्रतीक्षा समय न्यूनतम)। राउंड रॉबिन: निश्चित टाइम क्वांटम पर आधारित प्रीमेप्टिव शेड्यूलिंग।
  • Deadlock & 4 Coffman Conditions: Deadlock occurs when set of processes are blocked waiting for resources held by each other. ALL 4 conditions must hold simultaneously: 1. Mutual Exclusion, 2. Hold and Wait, 3. No Preemption, 4. Circular Wait. Banker's Algorithm (Dijkstra): Resource allocation algorithm used for deadlock avoidance by verifying safe state. डेडलॉक एवं 4 कॉफमैन शर्तें: जब प्रोसेस एक-दूसरे के संसाधनों की प्रतीक्षा में हमेशा के लिए अटक जाएं। सभी 4 शर्तें एक साथ होना अनिवार्य: 1. म्यूचुअल एक्सक्लूजन, 2. होल्ड एंड वेट, 3. नो प्रीएम्पशन, 4. सर्कुलर वेट। बैंकर्स एल्गोरिदम: डेडलॉक से बचाव (Safe State) हेतु प्रयुक्त।
  • Virtual Memory & Thrashing: Extends physical RAM using secondary storage (swap space). Uses Paging (fixed-size blocks). Page Fault: CPU accesses page not present in RAM; OS fetches it from disk. Thrashing: State where system spends more time swapping pages than executing instructions, dropping CPU utilization to near zero. वर्चुअल मेमोरी व थ्रैशिंग: हार्ड डिस्क के स्पेस को अतिरिक्त रैम (स्वैप स्पेस) के रूप में प्रयुक्त करना। पेज फॉल्ट: जब मांगा गया पेज रैम में न मिले। थ्रैशिंग: जब CPU वास्तविक निष्पादन छोड़कर केवल पेज की अदला-बदली (स्वैपिंग) में फंसा रह जाए और गति शून्य हो जाए।
UPSSSC Top Note: Banker's algorithm is used for Deadlock Avoidance; Thrashing occurs due to excessive page faults; Round Robin uses Time Quantum! UPSSSC मुख्य बिंदु: बैंकर्स एल्गोरिदम डेडलॉक से बचाव हेतु प्रयुक्त होता है; अत्यधिक पेज फॉल्ट्स से थ्रैशिंग होती है; राउंड रॉबिन में टाइम क्वांटम का उपयोग होता है!

1. Operating System: Architecture, Kernel & OS Classifications 1. ऑपरेटिंग सिस्टम: वास्तुकला, कर्नल एवं ओएस का वर्गीकरण
  • Definition & Dual-Mode Operation:
    • An Operating System (OS) is foundational system software that manages computer hardware resources (CPU, RAM, storage, I/O) and provides a secure execution environment for applications.
    • Dual Mode Operation: To prevent rogue user programs from crashing the system, the CPU executes in two distinct modes:
      • User Mode (Non-privileged / Ring 3): User applications run here with restricted hardware access.
      • Kernel / Supervisor Mode (Privileged / Ring 0): The core OS kernel executes here with direct, unrestricted hardware execution rights. Transitions occur via System Calls (Syscalls).     परिभाषा एवं डुअल-मोड संचालन:
    • ऑपरेटिंग सिस्टम (OS) एक आधारभूत सिस्टम सॉफ्टवेयर है जो कंप्यूटर हार्डवेयर (सीपीयू, रैम, स्टोरेज, इनपुट/आउटपुट) का प्रबंधन करता है एवं यूजर और हार्डवेयर के मध्य इंटरफेस प्रदान करता है।
    • ड्यूल मोड संचालन: सिस्टम सुरक्षा हेतु सीपीयू दो स्तरों पर कार्य करता है:
      • यूज़र मोड (Ring 3): यूजर प्रोग्राम इस गैर-विशेषाधिकार प्राप्त मोड में चलते हैं।
      • कर्नल / सुपरवाइज़र मोड (Ring 0): ओएस का मुख्य कर्नल इस विशेषाधिकार प्राप्त मोड में सीधे हार्डवेयर को नियंत्रित करता है; यूज़र प्रोग्राम सिस्टम कॉल (System Call) के माध्यम से कर्नल से सेवा मांगते हैं।
  • Kernel Types:
    • Kernel: The central core component of an OS loaded into memory during booting; remains in RAM throughout system uptime.
    • Monolithic Kernel: All OS services (process management, memory, file system, device drivers) run inside a single large kernel space in Ring 0 (e.g., Linux, Unix, MS-DOS). Faster execution, but a bug in any driver can crash the entire system.
    • Microkernel: Only essential mechanisms (IPC, basic scheduling, memory mapping) reside in kernel space; drivers and file systems run in user space (e.g., Minix, QNX). Highly stable and crash-resistant, but slower IPC.     कर्नल के प्रकार:
    • कर्नल (Kernel): ऑपरेटिंग सिस्टम का केंद्रीय हृदय (Core); बूटिंग के समय रैम में लोड होता है और कंप्यूटर बंद होने तक रैम में बना रहता है।
    • मोनोलिथिक कर्नल: सभी सेवाएं (मेमोरी, डिवाइस ड्राइवर, फाइल सिस्टम) एक ही कर्नल स्पेस में चलती हैं (उदा: लिनक्स, यूनिक्स, डॉस); तीव्र गति, किंतु ड्राइवर क्रैश होने पर पूरा सिस्टम क्रैश हो सकता है।
    • माइक्रोकर्नल: केवल न्यूनतम आवश्यक सेवाएं कर्नल में रहती हैं, बाकी यूजर स्पेस में चलती हैं (उदा: Minix, QNX); अत्यधिक स्थिर।
  • Classification of Operating Systems:
    • Batch Operating System: Similar jobs are grouped into batches and processed sequentially without human user intervention (e.g., early IBM mainframes).
    • Multiprogramming OS: Keeps multiple programs in main memory simultaneously; when one program waits for I/O, the CPU switches to another program, maximizing CPU utilization.
    • Time-Sharing / Multitasking OS: CPU switches between active processes so rapidly using small time slices (Time Quanta) that users perceive concurrent execution (e.g., Windows, Linux, macOS).
    • Real-Time Operating System (RTOS): Guaranteed completion of tasks within strict deterministic deadlines (hard real-time vs soft real-time); used in missile guidance, industrial robots, pacemaker medical implants, automotive ABS (e.g., VxWorks, RTLinux, QNX).
    • Distributed OS: Manages a collection of independent networked computers appearing to the user as a single coherent system.     ऑपरेटिंग सिस्टम का वर्गीकरण:
    • बैच ऑपरेटिंग सिस्टम: एक जैसे कार्यों को बैच में समूहीकृत कर बिना मानवीय हस्तक्षेप के क्रमानुसार प्रोसेस किया जाता है।
    • मल्टीप्रोग्रामिंग ओएस: मुख्य मेमोरी में एक साथ कई प्रोग्राम रखे जाते हैं; एक प्रोग्राम द्वारा I/O प्रतीक्षा करने पर सीपीयू दूसरे प्रोग्राम पर स्विच कर सीपीयू दक्षता बढ़ाता है।
    • टाइम-शेयरिंग / मल्टीटास्किंग: सीपीयू समय को छोटे-छोटे टुकड़ों (टाइम स्लाइस/क्वांटम) में विभाजित कर कई प्रोग्रामों को लगभग एक साथ चलाता है (उदा: विंडोज, लिनक्स, मैकओएस)।
    • रियल-टाइम ऑपरेटिंग सिस्टम (RTOS): कार्यों को पूर्व-निर्धारित अत्यंत सख्त समय-सीमा (Deadlines) में पूरा करता है; मिसाइल गाइडेंस, रोबोटिक्स, सैटेलाइट, मेडिकल वेंटिलेटर में प्रयुक्त (उदा: VxWorks, RTLinux)।
    • डिस्ट्रिब्यूटेड ओएस: कई स्वतंत्र नेटवर्क कंप्यूटरों को एकल सिस्टम के रूप में प्रबंधित करता है।
2. Process Scheduling, Virtual Memory & File Systems 2. प्रोसेस शेड्यूलिंग, वर्चुअल मेमोरी एवं फाइल सिस्टम
  • Process States & CPU Scheduling Algorithms:
    • Process Lifecycle States: New → Ready → Running → Waiting (Blocked) → Terminated.
    • FCFS (First-Come, First-Served): Non-preemptive; processes executed in arrival order; suffers from the Convoy Effect (short processes stuck behind long CPU-bound jobs).
    • SJF (Shortest Job First): Selects process with smallest CPU burst time; optimal average waiting time; risk of Starvation for longer jobs.
    • Round Robin (RR): Preemptive; cyclic allocation using a fixed Time Quantum; universally used in time-sharing interactive OS.
    • Deadlock (गतिरोध): A condition where two or more processes are permanently blocked, each holding a resource and waiting for another resource held by the other. Coffman's 4 conditions: Mutual Exclusion, Hold & Wait, No Preemption, Circular Wait.     प्रोसेस अवस्थाएं एवं शेड्यूलिंग एल्गोरिदम:
    • प्रोसेस के 5 जीवन चक्र: New (नई) → Ready (तैयार) → Running (सक्रिय) → Waiting/Blocked (प्रतीक्षारत) → Terminated (समाप्त)।
    • FCFS (पहले आओ, पहले पाओ): आगमन क्रम में निष्पादन; कॉन्वॉय प्रभाव (Convoy Effect) से ग्रसित।
    • SJF (शॉर्टेस्ट जॉब फर्स्ट): सबसे छोटे कार्य को पहले चुनता है; न्यूनतम औसत प्रतीक्षा समय।
    • राउंड रॉबिन (Round Robin): प्रत्येक प्रोसेस को एक निश्चित टाइम क्वांटम (Time Quantum) आवंटित किया जाता है; टाइम-शेयरिंग सिस्टम का मुख्य आधार।
    • डेडलॉक (Deadlock): ऐसी स्थिति जब दो या दो से अधिक प्रक्रियाएं एक-दूसरे द्वारा रोके गए संसाधनों की प्रतीक्षा में सदैव के लिए अटक जाती हैं।
  • Virtual Memory & Paging:
    • Virtual Memory: An OS memory management technique that creates an illusion of a large contiguous physical memory space by mapping virtual addresses to physical RAM and secondary hard disk space (Swap Space / Pagefile.sys).
    • Paging: Memory divided into fixed-size blocks: physical memory blocks are called Frames; logical memory blocks are called Pages (typically 4 KB).
    • Page Fault: An interrupt generated when an active program requests a page that is not currently loaded into physical RAM.
    • Thrashing (थ्रैशिंग): A catastrophic system degradation state where the CPU spends more time swapping pages back and forth between RAM and disk than executing actual instructions.     वर्चुअल मेमोरी एवं पेजिंग:
    • वर्चुअल मेमोरी: भौतिक रैम (RAM) की सीमा से बड़े प्रोग्रामों को चलाने हेतु हार्ड डिस्क के एक हिस्से को अस्थायी मेमोरी (Swap Space) के रूप में प्रयोग करने की तकनीक।
    • पेजिंग (Paging): लॉजिकल मेमोरी को निश्चित आकार के ब्लॉकों (Pages) में और फिजिकल रैम को (Frames) में विभाजित करना।
    • पेज फॉल्ट (Page Fault): जब प्रोग्राम किसी ऐसे पेज की मांग करता है जो वर्तमान में रैम में मौजूद नहीं है, तब पेज फॉल्ट उत्पन्न होता है।
    • थ्रैशिंग (Thrashing): अत्यधिक पेज फॉल्ट के कारण सीपीयू द्वारा वास्तविक निष्पादन करने के बजाय अधिकांश समय हार्ड डिस्क और रैम के बीच पेजों की अदला-बदली (Swapping) में बर्बाद करने की स्थिति।
  • File Systems Architecture:
    • FAT32 (File Allocation Table): Legacy file system supported across all OS; max single file size limit is 4 GB; max partition size 2 TB.
    • NTFS (New Technology File System): Modern default Windows file system; supports journaling, file encryption (EFS), compression, access permissions (ACL), and massive files up to 16 TB+.
    • ext4 (Fourth Extended Filesystem): Standard default journaling file system for Linux distributions.
    • APFS (Apple File System): Optimized for flash SSD storage on macOS and iOS.     फाइल सिस्टम वास्तुकला:
    • FAT32: पुराना फाइल सिस्टम; किसी एकल फाइल का अधिकतम आकार केवल 4 GB हो सकता है।
    • NTFS (विंडोज): आधुनिक विंडोज का मानक फाइल सिस्टम; जर्नलिंग, फाइल एन्क्रिप्शन, एक्सेस अनुमतियां और विशाल फाइल आकार का समर्थन।
    • ext4: लिनक्स ऑपरेटिंग सिस्टम का मानक डिफॉल्ट फाइल सिस्टम।
    • APFS: ऐप्पल मैकओएस एवं आईओएस का आधुनिक सॉलिड-स्टेट फाइल सिस्टम।

4. E-Governance: 4 Interaction Models & National Digital Initiatives 4. ई-गवर्नेंस: 4 संपर्क मॉडल एवं प्रमुख राष्ट्रीय डिजिटल पहलें
  • The 4 E-Governance Interaction Models:
    • G2C (Government-to-Citizen): Direct delivery of public services to citizens (e.g., Aadhaar portal, DigiLocker, passport online seva, electricity bill payment, e-District services).
    • G2B (Government-to-Business): Electronic interfaces between government and commercial business enterprises (e.g., GSTN portal, MCA21 corporate filings, GeM e-bidding, trade licenses).
    • G2G (Government-to-Government): Seamless electronic information sharing between central, state, and local administrative bodies (e.g., Smart Governance intranets, PRAGATI, CCTNS crime tracking network).
    • G2E (Government-to-Employee): Internal administrative automation for government personnel (e.g., online GPF, SPARROW appraisal system, e-Office, pension tracking).     ई-गवर्नेंस के 4 प्रमुख संपर्क मॉडल:
    • G2C (सरकार-से-नागरिक): नागरिकों को सीधे सरकारी सेवाओं का वितरण (उदा: आधार, डिजिलॉकर, ऑनलाइन पासपोर्ट सेवा, ई-डिस्ट्रिक्ट)।
    • G2B (सरकार-से-व्यापार): सरकार और व्यावसायिक उद्यमों के मध्य डिजिटल सेवाएं (उदा: जीएसटी पोर्टल, एमसीए21 कंपनी पंजीकरण, GeM टेंडर)।
    • G2G (सरकार-से-सरकार): विभिन्न सरकारी विभागों, केंद्र एवं राज्य सरकारों के मध्य डेटा साझाकरण (उदा: PRAGATI समीक्षा प्रणाली, CCTNS पुलिस नेटवर्क)।
    • G2E (सरकार-से-कर्मचारी): सरकारी कर्मचारियों हेतु आंतरिक डिजिटल सेवाएं (उदा: ई-ऑफिस, ऑनलाइन पीएफ व पेंशन पोर्टल, स्पैरो ACR)।
  • National Digital Flagship Initiatives:
    • National e-Governance Plan (NeGP): Formulated in May 2006 comprising 31 Mission Mode Projects (MMPs) implemented across Central, State, and Integrated levels.
    • Digital India Programme: Launched on 1 July 2015 by Prime Minister Narendra Modi based on 9 Pillars (Broadband Highways, Universal Mobile Access, Public Internet Access, e-Governance, e-Kranti, Information for All, Electronics Manufacturing, IT for Jobs, Early Harvest Programmes).
    • DigiLocker: Flagship cloud storage initiative under Digital India launched in 2015. Provides every Aadhaar-linked citizen with 1 GB free secure cloud storage. Issued electronic documents in DigiLocker carry legal parity with physical originals under Rule 9A of Information Technology (Preservation and Retention of Information) Rules, 2016.
    • UMANG (Unified Mobile Application for New-age Governance): Launched in November 2017; multi-lingual unified mobile gateway providing single-app access to over 1,500+ Central and State government services (EPFO, PAN, Aadhaar, DigiLocker, Gas booking).
    • GeM (Government e-Marketplace): Online public procurement portal launched in August 2016 by Ministry of Commerce and Industry to facilitate transparent, contactless procurement of goods and services by all government ministries, departments, and PSUs.
    • PRAGATI: Pro-Active Governance and Timely Implementation launched in 2015; multi-modal platform chaired by the Prime Minister integrating video conferencing, cloud, and GIS to review mega infrastructure projects.
    • BharatNet: World's largest rural broadband project aiming to connect all 2.5 lakh Gram Panchayats across India via high-speed optical fiber cable (OFC) network.     राष्ट्रीय डिजिटल पहलें एवं महत्वपूर्ण कार्यक्रम:
    • राष्ट्रीय ई-गवर्नेंस योजना (NeGP): मई 2006 में 31 मिशन मोड प्रोजेक्ट्स (MMPs) के साथ स्वीकृत।
    • डिजिटल इंडिया कार्यक्रम: 1 जुलाई 2015 को प्रधानमंत्री नरेंद्र मोदी द्वारा प्रारंभ; 9 स्तंभों (Pillars) पर आधारित।
    • डिजिलॉकर (DigiLocker): 2015 में प्रारंभ; प्रत्येक आधार-सत्यापित नागरिक को 1 GB का निःशुल्क सुरक्षित क्लाउड स्पेस प्रदान करता है। सूचना प्रौद्योगिकी अधिनियम के नियम 9A के तहत डिजिलॉकर में उपलब्ध डिजिटल दस्तावेज मूल भौतिक दस्तावेजों के समान कानूनी मान्यता रखते हैं।
    • उमंग (UMANG): Unified Mobile Application for New-age Governance; नवंबर 2017 में लॉन्च; 1500+ केंद्रीय व राज्य सरकारी सेवाओं (EPFO, पैन, आधार आदि) हेतु एकीकृत एकल मोबाइल ऐप।
