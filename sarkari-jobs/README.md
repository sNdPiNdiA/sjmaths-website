# SJMaths Sarkari Jobs - Automated Job Notification Pipeline

Auto-discovers new government job notifications from official Indian portals, extracts structured information from the official PDFs, and publishes SEO-friendly static pages to https://sjmaths.com/sarkari-jobs/.

**Target latency**: notification published by department -> live on SJMaths within 6 hours.

## Pipeline (one cron tick)

```
[1] fetch-notifications.js   scrape 7 official portals -> scripts/raw/YYYY-MM-DD.json
[2] download-pdf.js          fetch each PDF -> sarkari-jobs/pdfs/<id>.pdf
[3] extract_pdf.py           pdfplumber text + OCR fallback -> sarkari-jobs/extracted-text/<id>.txt
[4] parse_fields.js          regex over text -> scripts/parsed/<id>.json
[5] generate-page.js         sarkari-jobs/<slug>/index.html
[6] update-database.js       append to data/jobs.json + data/processed.json
[7] update-hub.js            overwrite sarkari-jobs/index.html from jobs.json
```

Each step is **idempotent** - re-running the pipeline on the same day is a no-op for already-processed items.

## Phase 1 portals (7)

- **SSC** - Staff Selection Commission
- **RRB** - Railway Recruitment Boards
- **IBPS** - Institute of Banking Personnel Selection
- **SBI** - State Bank of India
- **UPPSC** - Uttar Pradesh Public Service Commission
- **UPSSSC** - UP Subordinate Services Selection Commission
- **UPPRPB** - UP Police Recruitment & Promotion Board

Phase 2 (config-only for now): UPSC, RBI, NABARD, LIC, EPFO, ESIC, ISRO, DRDO.

All portal config lives in `scripts/config/portals.json`. Adding a new portal is a JSON edit - no code change.

## Local development

```bash
# 1. Install Node deps
npm ci

# 2. (First time) install Python deps
pip install -r sarkari-jobs/scripts/requirements.txt
# Linux/macOS also need: poppler-utils, tesseract-ocr, tesseract-ocr-hin, tesseract-ocr-eng

# 3. List pipeline steps and verify config
npm run sj:dry-run
# Verified locally on this checkout: the dry-run reports 7/7 enabled portals and the full step sequence.

# 4. Run individual steps
npm run sj:fetch
npm run sj:download
npm run sj:extract
npm run sj:parse
npm run sj:generate
npm run sj:database
npm run sj:hub

# 5. Or run the full pipeline
npm run sj:orchestrator
```

## Production cron

The scheduled workflow is now implemented in `.github/workflows/sarkari-jobs.yml` and runs `npm run sj:orchestrator` every 6 hours:

| UTC   | IST   |
| ----- | ----- |
| 00:30 | 06:00 |
| 06:30 | 12:00 |
| 12:30 | 18:00 |
| 18:30 | 00:00 |

The workflow commits the generated files to `main`. Firebase Hosting auto-deploys on push.

## Safety nets

- **Duplicate detection**: sha1(portalId + pdfUrl) + Jaccard >= 0.85 on normalised title.
- **Low-confidence gate**: items missing `vacancy` OR `applyEnd` go to `scripts/quarantine/` and are **not published**.
- **Idempotency**: re-running the same day skips already-processed ids.
- **Cap**: `data/jobs.json` keeps at most 500 most-recent jobs (oldest dropped).

## Adding a new portal

1. Open `sarkari-jobs/scripts/config/portals.json`.
2. Add a new entry under `portals`. Copy the structure from an existing portal (e.g. `ssc`).
3. Set `enabled: true` once selectors are verified against the live page.
4. Run `npm run sj:fetch` and check `sarkari-jobs/scripts/raw/<today>.json` for output.

## Adding a new mode (admit-card, result, answer-key, syllabus)

The pipeline is mode-agnostic. Reuse the same scripts by:

1. Adding a `mode` field to each portal entry (default `"notification"`).
2. Branching the page template inside `generate-page.js` on `mode`.
3. Adding a module landing page (e.g. `sarkari-jobs/admit-cards/index.html`).

The aggregator fallback (SarkariResult) and the same fetch/extract/parse chain serve all modes.
