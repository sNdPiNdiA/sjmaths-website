What this chapter is teaching

An algorithm is a precise, finite sequence of steps that transforms input into a result. This chapter moves from familiar addition to efficient algorithms for divisors, gcd, lcm, primes and prime factorisation.

PreciseEvery instruction must say exactly what to do.
FiniteThe process must stop after a limited number of steps.
CorrectThe output must satisfy the problem for every allowed input.
EfficientGood algorithms reduce unnecessary checks and repeated work.
Study tip: Trace an algorithm on paper using a table of variables. At every step, record what changed and why the next step is allowed.
Coverage check: These notes cover all methods needed for Exercises 11.1–11.3 and the end-of-chapter questions. The supplied exercise text does not include any hidden textbook diagrams or additional algorithms, so the answers below state their assumptions clearly.

1What makes an algorithm?

An algorithm is a well-defined procedure for solving a class of problems, not just one worked answer.

InputIdentify the values or lists given to the procedure.
StepsUse unambiguous instructions in a fixed order.
OutputState exactly what the procedure must produce.
TerminationShow why the process eventually stops.
  • Do not silently add an action that the written steps do not mention.
  • State clearly when the process stops, such as “continue until the second number becomes zero.”
  • Test normal cases, boundary cases and cases that produce an extra carry or remainder.

2Column addition and carry

Align numbers by place value, start at the units column, and move from right to left.

Decimal addition algorithm:
  1. Write the numbers one below the other with units, tens, hundreds and so on aligned.
  2. Begin with carry 0.
  3. For each column from right to left, add the two digits and the carry. Write the units digit of the sum and carry the tens digit.
  4. Move one column left and continue until every column has been processed.
  5. If the final carry is 1, write it to the left of the answer.
  • Missing leading digits are treated as 0, so a 5-digit number can be added to a 3-digit number after right alignment.
  • Right alignment is essential because each column must contain equal place values.
  • The largest column total is 9 + 9 + 1 = 19, so a decimal carry can only be 0 or 1.
  • The final-carry step matters for results such as 9999 + 1 = 10000.

3Searching two increasing lists

Because both lists are sorted, compare the current entries in order instead of comparing every element with every other element.

To find elements in List 1 that are not in List 2:
  1. Begin with the first entry of each list.
  2. Compare the current entries. If the List 1 entry is smaller, write it in the answer and move to the next entry in List 1.
  3. If the entries are equal, move to the next entry in both lists.
  4. If the List 2 entry is smaller, move to the next entry in List 2.
  5. When List 2 ends, write all remaining entries of List 1.

Exchange the names of the lists to obtain the elements in List 2 that are not in List 1.

Why it is efficient: Each entry is passed only once, so the total number of comparisons is at most the number of entries in the two lists together.
  • Sorted order lets us discard a smaller value permanently when it cannot match a later, larger value.
  • If repeated values are allowed, first state whether the answer should contain each distinct value once or preserve repetitions.

4Divisors and factor pairs

A positive integer d is a divisor of n when division by d leaves remainder 0. Divisors occur in pairs: if d divides n, then n divided by d is also a divisor.

d × (n ÷ d) = n
  • Checking every number from 1 to n always works but may do unnecessary work.
  • Every factor pair has one member at most √n, so checking the numbers from 1 through floor(√n) finds both members.
  • If n is a perfect square, √n is a single divisor and must not be written twice.
  • When listing divisors in reverse order, the same divisibility test works; only the output order changes.
Factor-pair steps:
  1. Examine each number from 1 through floor(√n).
  2. If the number divides n exactly, write the number and its paired divisor, n divided by that number.
  3. If the two members are equal, write the middle divisor only once.

5Gcd: common divisors and Euclid’s algorithm

The greatest common divisor, gcd(m,n), is the largest positive integer that divides both m and n.

Euclid’s algorithm:
  1. Take the two numbers m and n, with m at least as large as n.
  2. Divide m by n and find the remainder.
  3. Replace m by n and replace n by the remainder.
  4. Repeat the division until the remainder is 0.
  5. The last non-zero remainder is the gcd.
gcd(m,n) = gcd(n, remainder when m is divided by n)
  • The remainder is smaller than n, so the second number decreases and the algorithm must terminate.
  • Starting at the smaller number and moving backwards, the first common divisor found is the gcd.
  • Euclid’s algorithm is usually faster because it skips direct examination of most possible divisors.
Calculation rule: Write every division in the form dividend = quotient × divisor + remainder. The last non-zero remainder is the answer.

6Lcm and its relationship with gcd

The least common multiple, lcm(m,n), is the smallest positive number divisible by both m and n.

lcm(m,n) = (m × n) ÷ gcd(m,n)
  1. Find the gcd of the two positive numbers.
  2. Divide one number by the gcd.
  3. Multiply the quotient by the other number.
  4. The product is the lcm.
  • A multiple-list method also works: list multiples of the larger number until one is divisible by the other, but it can be slow.
  • For coprime numbers, gcd = 1 and lcm = m × n.

7Prime numbers and prime divisors

A prime number is an integer greater than 1 with exactly two distinct positive divisors: 1 and itself.

Steps for checking whether n is prime:
  1. If n is less than 2, it is not prime.
  2. Find all the divisors of n.
  3. If the list has exactly two different divisors, 1 and n, then n is prime. Otherwise it is not prime.

A shorter method is to examine possible divisors from 2 through floor(√n). If any one divides n exactly, n is not prime.

Steps for finding prime divisors:
  1. Find all the divisors of n.
  2. Check each divisor using the prime-number test.
  3. Write only the divisors that are prime.
  • For n = 1, the divisor list is [1], so 1 is not prime.
  • For n = p², the divisor pair p × p contributes only one distinct middle divisor.
  • Prime divisors are distinct factors; prime factorisation additionally records their exponents.

8Prime factorisation

Every integer greater than 1 can be written as a product of primes. The prime factorisation is unique apart from the order of the factors.

Prime-factorisation steps:
  1. Begin with the smallest prime number, 2.
  2. If it divides the number exactly, write 2 as a factor and divide the number by 2. Continue until 2 no longer divides it.
  3. Try the next possible divisor and repeat the division process.
  4. Stop when the square of the divisor being tested is greater than the remaining number.
  5. If the remaining number is greater than 1, it is the final prime factor.
180 = 2 × 2 × 3 × 3 × 5 = 22 × 32 × 51
  • Represent a factorisation as a prime-and-exponent table, such as 2 → 2, 3 → 2 and 5 → 1, or as the ordered list [2, 2, 3, 3, 5].
  • To compare two factorisations, compare the exponent of each prime, treating a missing prime as exponent 0.
  • For gcd, take the minimum exponent of each common prime. For lcm, take the maximum exponent of every prime appearing.

9Correctness, efficiency and testing

TraceFollow every instruction on a small example.
BoundaryTest 0, 1, equal values, different lengths and perfect squares.
InvariantCheck what remains true after every repetition.
StopExplain why the process cannot continue forever.
  • For addition, the processed right-hand columns already contain their correct answer digits.
  • For Euclid’s algorithm, the common divisors do not change when the pair (m,n) is replaced by n and the remainder from dividing m by n.
  • For divisor-pair search, every divisor below √n is paired with one at or above √n.
  • Correctness is about the result; efficiency is about how much work is needed to obtain it.

Exercise Set 11.1 — Solutions

Precise column addition, place value and the final carry.

1Add two 4-digit numbers using the steps we have written down. Make sure you follow the steps precisely; do not perform any action that is not explicitly mentioned. Are you able to obtain the correct result?
Answer / method
Yes. For example, 4,738 + 2,695: units 8+5=13, write 3 and carry 1; tens 3+9+1=13, write 3 and carry 1; hundreds 7+6+1=14, write 4 and carry 1; thousands 4+2+1=7. The answer is 7,433. The procedure works because each column is processed once and the final carry is handled.
2What happens if you add a 5-digit number to a 3-digit number? Do our steps handle this situation correctly?
Answer / method
Right-align the numbers and treat missing leading digits as 0. For example, 42,718 + 563 is 42,718 + 00,563. The same column steps work; after the last 5-digit column, write any final carry.
3Why is it important to align the columns from right to left?
Answer / method
Right alignment places units under units, tens under tens, hundreds under hundreds, and so on. Without it, digits with different place values would be added together and the result would be incorrect.
4In Step 3, why cannot the value of carry be more than 1?
Answer / method
In one decimal column the largest possible total is 9 + 9 + 1 = 19. The units digit is written in the column and the tens digit is either 0 or 1, so carry can never exceed 1.
5What happens if we do not include the fifth step in the algorithm above? Give examples where the algorithm will work correctly and where it will fail to work.
Answer / method
The algorithm works when the most significant column produces no carry beyond the written columns, for example 1,234 + 2,345 = 3,579. It fails when a final carry is needed, for example 9,999 + 1 = 10,000; without Step 5, the leading 1 is lost and the result appears as 0000.

Exercise Set 11.2 — Solutions

Sorted-list comparison, lcm and factor-pair reasoning.

1Suppose List 1 and List 2 are two lists of numbers in increasing order. (i) Write an algorithm to find elements in List 1 that are not present in List 2. (ii) Write an algorithm to find elements in List 2 that are not present in List 1.
Answer / method
Assume the lists contain distinct values. Begin with the first entry of each list. Compare the current entries: if the List 1 entry is smaller, write it and move to the next List 1 entry; if they are equal, move to the next entry in both lists; if the List 2 entry is smaller, move to its next entry. When List 2 ends, write the remaining List 1 entries. Exchange the lists to find the entries in List 2 that are not in List 1. Each entry is examined at most once.
2Describe an algorithm to compute the least common multiple (lcm) of two numbers.
Answer / method
For positive m and n, first compute g = gcd(m,n) using Euclid’s algorithm. Then return lcm(m,n) = (m/g)×n. Dividing before multiplying helps avoid a large intermediate product. Alternatively, list multiples of the larger number until one is divisible by the other.
*3Divisors occur in pairs. For instance, the divisors of 18 are (1, 18), (2, 9) and (3, 6). (i) If we write out divisors in pairs, how many numbers do we have to examine between 1 and n to find all the divisors of n? (ii) If we list out the divisors in pairs, will our gcd algorithm still work in the manner we have described?
Answer / method
(i) It is enough to examine the integers from 1 through floor(√n), so floor(√n) numbers. Whenever one divides n exactly, write both that number and its paired divisor, n divided by that number. If the two members are equal, write the middle divisor only once. (ii) Yes, provided both members of every pair are included and the common divisors are compared correctly. Euclid’s algorithm itself does not need divisor pairs and remains unchanged.

Exercise Set 11.3 — Solutions

Reverse scans for divisors and common divisors.

1How would our original algorithm change if we computed the divisors of n by examining the numbers from 1 to n in reverse order, from n down to 1?
Answer / method
Begin with n and examine the numbers in the order n, n−1, n−2, and so on down to 1. Whenever the number divides n exactly, write it as a divisor. The result is the same divisor set but in descending order. The number of possible numbers examined is still n, so reversing the order does not by itself reduce the work.
2What about the last algorithm described above? What happens when we look at common divisors starting from min(m, n) and work backwards to 1?
Answer / method
Begin with the smaller of m and n and work backwards to 1. At each step check whether the number divides both m and n exactly. The first common divisor found is the gcd, so the process may stop immediately. If every common divisor is required, continue checking down to 1.

End-of-Chapter Exercises — Solutions

Use Euclid’s algorithm, divisors and prime factorisation to solve these mixed problems.

1Compute the following using the improved version of Euclid's algorithm. (i) gcd(375, 825) (ii) gcd(51000, 81000) (iii) gcd(1789287, 237656) (iv) gcd(2587392, 157656)
Answer / method
(i) 825 = 2×375 + 75; 375 = 5×75 + 0, so gcd(375,825)=75. (ii) 81000=1×51000+30000; 51000=1×30000+21000; 30000=1×21000+9000; 21000=2×9000+3000; 9000=3×3000+0, so gcd=3000. (iii) The remainders are 125695, 111961, 13734, 2089, 1200, 889, 311, 267, 44, 3, 2, 1, 0, so gcd=1. (iv) The remainders are 64896, 27864, 9168, 360, 168, 24, 0, so gcd=24.
2Assume that m ≥ n. Verify that d divides m and n if and only if d divides both n and m mod n.
Answer / method
Write m as q×n + r, where r is the remainder when m is divided by n. If d divides both m and n, then d divides m−q×n, which is r. Conversely, if d divides n and r, then d divides q×n+r, which is m. Therefore d divides both m and n exactly when d divides both n and the remainder obtained on dividing m by n.
3Write an algorithm prime(n) to check if n is prime. (Hint: A prime number p has exactly two distinct factors, 1 and p. Can you make use of divisors(n) to write out prime(n)?)
Answer / method
Steps for checking whether n is prime: (1) If n is less than 2, state that n is not prime. (2) Find all the divisors of n. (3) If the only divisors are 1 and n, state that n is prime; otherwise state that it is not prime. A shorter calculation examines possible divisors from 2 through floor(√n). If one divides n exactly, n is not prime; if none does, n is prime.
*4Write an algorithm primedivisors(n) to compute the list of divisors of n that are prime numbers. (Hint: Compute divisors(n) and then filter out the primes in this list …)
Answer / method
Steps for finding prime divisors: (1) Find all the divisors of n. (2) Test each divisor using the prime-number steps. (3) Write only the divisors that are prime. The number 1 is automatically excluded because it is not prime. For example, the prime divisors of 180 are 2, 3 and 5.
*5We can also find the gcd of two numbers by computing the prime factorisation of both the numbers. Try to write an algorithm to compute the prime factorisation of a number. (i) The prime factorisation of 180 is 2² × 3² × 5¹. How would you represent this? (ii) How would you compare the prime factorisations of two numbers?
Answer / method
Use repeated division. Begin with 2 and divide the number by 2 as long as the division is exact, writing 2 each time. Then try the next possible divisor and repeat. Stop when the square of the divisor being tested is greater than the remaining number. If the remaining number is greater than 1, write it as the final prime factor. For 180: 180 = 2×90 = 2×2×45 = 2×2×3×15 = 2×2×3×3×5, so the representation is 2²×3²×5¹. To compare two factorisations, make a list of every prime and its exponent, using exponent 0 when a prime is absent. For gcd use the smaller exponent of each common prime; for lcm use the larger exponent of every prime present.
Method note: The solutions use ordinary mathematical statements, numbered algorithm steps and calculations. “Remainder” means what is left after one number is divided by another.
